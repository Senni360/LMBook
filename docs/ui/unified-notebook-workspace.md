# Unified notebook workspace

Owner direction, 2026-09-16: notebooks and Obsidian vaults share one navigation and workspace; notes on the left, reading/editing in the centre, learning tools on the right. Keep Ink's drawn controls and add drawn pane outlines, persisted resizers, light/dark/system and five accents. Local model installation must be distinguishable from readiness and enablement.

## Implemented behavior

- PR #9 preserves 0.3.12. Follow-up work is on `feat/unified-notebook-workspace`.
- Existing active vaults receive a stable paired notebook. Open folder as notebook uses the desktop folder picker; files remain in place. Ordinary notebooks create managed Markdown folders in app data. Sources copied into a new notebook become its own editable Markdown files, retaining original vault provenance in `vaultOrigin` and original attachments where available.
- Saving Markdown and explicitly syncing notes updates current learning sources. Sync also runs on opening or refocusing the workspace. File removals retain earlier learning sources with a notice. Removing a source from learning excludes its path from subsequent automatic imports and leaves the shared file intact. Reimporting it through selection tools makes it available again. Earlier chat/episode evidence remains in its historical snapshot.
- All sources are available to the established bounded context selection for questions/audio. Local E5 indexing is optional and powers meaning search in the note finder; it is not a chat model and does not replace Luna. Larger collections use selected passages rather than sending the entire vault to a provider.
- Source capacity is 2,000 current sources, aligned with notebook backup validation; individual reviewed imports retain their 150-note/5 MB batch cap. Sync reads up to 100 MB. Indexing retains its existing 20,000-passage/32 MB limits. Limits produce visible notices/errors, not claims of complete indexing.
- Three panes resize by pointer or keyboard and persist per notebook. Centre reading expands when adjacent panes are closed. Small screens show one task pane at a time. Draft summaries, source review, note recovery and conflict handling remain accessible.
- Appearance follows the OS by default, with explicit light/dark choices and Cobalt, Moss, Amber, Plum, Coral accents. Inputs keep their transparent drawn outline layer so values remain visible.
- Settings separates downloaded files, runtime availability and enablement. Check model performs an actual offline embedding without enabling the model. Notebook Search by meaning can check/enable local search and start indexing in one explicit action, with progress, Stop and Try a search. OpenRouter indexing has a separate action that explicitly sends notes and uses API credits.
- Export vault produces a ZIP of current Markdown and supported attachments, plus readable goals/conversations/flashcards/audio scripts and notebook JSON in a collision-safe metadata directory. Open the extracted folder as an Obsidian vault. Plugin code and account credentials are excluded; generated audio is exported separately or retained in the existing full LMBook backup. Export preflights its 512 MB bound and fails instead of silently truncating.

## Evidence and limitations

- Existing owner E5 checkpoint passed the Python offline smoke in approximately 10.5 seconds without changing owner state. The isolated app check returned a real 384-dimensional embedding in 10.995 seconds.
- Connected `D:/Downloads/PWS/vault` read-only through an isolated library: 291 notes imported in 1.267 seconds, zero warnings. E5 indexed 1,494 passages across all 291 notes; a cross-language query returned relevant dam-relocation passages. No edits were made to the original files. The vault exported successfully and its full LMBook backup restored to 291 managed Markdown notes with original vault provenance and zero duplicate imports.
- Browser behavior evaluation created and saved a Markdown note, observed the corresponding learning source, reloaded the saved text, and retained keyboard-adjusted pane widths. No page errors; all three panes had no horizontal overflow at 1600x1000.
- Visual review caught/fixed opaque contour layers hiding field values, white selected cards in dark mode, and pane-frame placement. Light and dark note-reader screenshots are in ignored `.work` evaluation artifacts.
- A live Luna request through Codex answered a separately authored saved-note question in 4.842 seconds with the correct source quotation. No PWS text was sent to Luna. No live paid OpenRouter request was made.
- 38 existing application tests passed; no new test files were added. Pointer resizing and reload persistence passed, as did dark-mode controls/chat/flashcard visual review. A constructed interrupted-install state returned to a stopped, retryable state instead of retaining a nonexistent running installer.
- Packaged Windows startup, sandbox, persistence and clean restart passed. The existing fixture now removes its temporary profile asynchronously with retries to avoid a Windows cleanup lock. Native export saved the authored Markdown and PDF/Canvas byte fixtures; excluding its learning source retained the file and prevented reimport. The actual dark native title bar/workspace was captured and visually reviewed, with no renderer errors.
- Obsidian's own plugin runtime and Sync are not embedded or evaluated here. Markdown is a shared filesystem interface, consistent with [Obsidian's documented storage model](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data). [Opening an existing folder as a vault](https://help.obsidian.md/Files+and+folders/Manage+vaults) is the export handoff.
- Large exports are bounded and preflighted in memory. Multiple app processes writing the same database are not a supported synchronization mechanism. Native Mac appearance/runtime validation remains separate from Windows evaluation. User acceptance and 0.4 approval remain pending.

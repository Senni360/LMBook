# Pre-0.4 application audit — 16 September 2026

The 0.3.14 Windows preview fixes four reproduced defects found in the unified workspace. This is a development evaluation, not approval to publish 0.4 or evidence of learning effectiveness. The owner still decides when the product is ready.

## Confirmed defects and fixes

| Priority | Reproduction and consequence | Fix and observed result |
| --- | --- | --- |
| High | Move a notebook with a shared folder to Trash. Its database relationship was deleted; startup could create a replacement notebook, and restoring the original could attach a different folder. | Preserve the relationship while trashed; reserve it until restore or permanent removal. An old-schema migration, Trash, restore, purge and explicit reconnect all passed in an isolated library. Restore retained the exact folder and vault ID. Permanent removal disconnected the folder without deleting its Markdown files. |
| High | Add a pasted source to a notebook containing 2,000 sources. The request succeeded, but the resulting 2,001-source notebook failed full-backup validation. | Enforce the existing capacity before pasted, document and audio imports publish a source. Reproduction now rejects the extra source with an explanation and retains 2,000 sources. Checks run under the artifact mutation lock. |
| Medium | A note beyond the supported folder depth produced a vault-scan warning, but workspace sync discarded it and appeared complete. | Carry scan warnings through to the existing “Notes synced with notices” interface. A 34-level fixture now reports its omitted material. |
| Medium | Narrow notebook panes crowded navigator filters and truncated filenames; the flashcard deck selector wrapped into a nearly unusable column. | Container-aware navigator controls, readable wrapping filenames and a full-width deck selector. Browser screenshots inspected; no document-wide horizontal overflow at 390, 600, 760 or 1,000 pixels. |

The Trash migration preserves associations still present when upgrading. It cannot safely infer an association already lost by an earlier version. A previously affected library needs inspection rather than automatic reassignment based on a similar name.

## Workflows exercised

- **Actual Luna generation:** four authored German/Dutch pairs, including ambiguous words, generated through the existing Codex connection in 10.10 seconds. All four exact supplied pairs and quoted rows were retained. This small case is not a general correctness guarantee; original-idiom coverage review remains necessary.
- **Practice:** unreviewed cards remained usable with visible status; the next answer stayed hidden; direction reversal reused the saved deck; typed answers advanced correctly. No physical game controller was used.
- **Failed word-list save:** a simulated HTTP 503 preserved the edited word, blocked practice with unsaved changes, and recovered the draft after reload. Removing the simulated failure saved it to the backend; the fixture was then restored.
- **Shared-file conflict:** an external edit while LMBook held an unsaved draft blocked overwrite. Saving the draft separately preserved both versions. Another unsaved editor draft survived reload.
- **Local meaning search:** a fresh real E5 runtime check returned 384 dimensions in 26.97 seconds. Two authored notes indexed successfully; the intended learning note ranked first. Changing its file excluded its stale search passage. Cancelling a subsequent indexing run stopped it. The worker was unloaded and the previous enablement setting restored.
- **Appearance and layout:** dark mode and Moss accent survived reload. Narrow-layout screenshots were inspected after the fixes. No renderer exceptions occurred in the scripted browser workflows.
- **Existing suite:** production TypeScript/Vite build and all 38 existing application tests passed after the fixes. No new formal automated test files were added; disposable reproduction/evaluation scripts and captures are ignored under `.work/release-audit/`.
- **Packaged Windows 0.3.14:** existing startup/sandbox/persistence/restart smoke passed. A visible native run exported a vault, preserved an excluded source's file, kept a trashed notebook absent during startup pairing, restored its exact folder and vault ID, and kept permanent removal from resurrecting it. Original files survived. Dark-mode capture inspected; no renderer exceptions observed.

The earlier 0.3.13 evaluation indexed the real PWS vault (291 notes, 1,494 passages) without changing its files. This audit used isolated authored fixtures for fault injection; it did not repeat that full large-vault run. Existing tests cover additional imports, backup formats, audio cache repair and cancellation, but are not live-provider or learner trials.

## Remaining before a 0.4 decision

1. Evaluate the current build natively on Apple Silicon and Intel Mac, including file permissions, external edits, installer behavior and CLI discovery. Windows results do not establish Mac compatibility.
2. Run a live OpenRouter connection and inference journey with an authorized account. No paid OpenRouter request was made in this audit. Luna and local E5 were actually executed.
3. Exercise physical controller practice and a complete current-build audio generation/listening session. Earlier short audio checks and automated cache checks do not cover those experiences.
4. Have the owner use their usual vault and review source selection, note editing, pane sizing and the model setup experience. Check representative idioom PDFs against their full expected vocabulary, including extraction and row pairing.
5. Resolve any findings from those journeys and obtain the owner's explicit 0.4 decision. Keep `release-policy.json` approval unset. The ten proposed background-assistant workflows remain separate unfinished scope; this release does not claim to implement them or Obsidian's plugin runtime.
